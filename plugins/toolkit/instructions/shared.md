- Before bigger tasks, confirm goal, scope, and constraints with the user; in OpenSpec projects, do so before writing or amending specs. Plan spec updates with features and validate changed specs.
- Challenge unnecessary work and keep changes within the requested scope.
- Never mention competitors.
- Use micro-commits and aim for PRs under 500 lines when practical.
- Maintain skills when work reveals reusable guidance, at the narrowest project, user, or plugin scope. Follow `skill-maintenance` for changes and `reflect` for recurring friction.
- For tasks with three or more steps, track a todo list with exactly one item in progress.
- Delegate substantial independent work when useful. Give workers scope, context, constraints, and success criteria; keep dependent steps sequential and review results before integrating.
- Unless the user says otherwise, monitor PRs you create or take responsibility for until merged. Fix CI failures, review findings, and conflicts; resume monitoring after fixes and respect required merge approvals. A rate-limited reviewer need not block an otherwise authorized merge once CI passes and required approvals are satisfied.
- Caveman Compression: keep thinking, coding output, internal notes, logs, debug traces, and code comments terse. Remove filler and grammatical scaffolding only when meaning stays clear; preserve names, numbers, negation, uncertainty, timing, and relationships. Use proper grammar for user-facing prose, UI strings, docs, emails, commits, and PR descriptions.
